# 异常处理：从 HTTP 成功到任务成功

> 本页保留旧 URL 与原导读练习，作为迁移入口。完整正文已迁至：[08 HTTP 成功之后，还有哪些失败](../02-verifiable/08-failures.md)。以下是历史导读，不代表当前示例的覆盖范围；运行与验收以新正文为准。

## 场景与目标

接口返回 200，但答案缺字段、引用不存在，或模型请求了无效工具。

## 从前端经验出发

像处理表单与接口错误一样分类：网络、限流、结构校验、业务校验、权限和任务质量问题。

## 类比的边界

不能统一 catch 后自动重试；生成可能重复收费，有副作用工具可能重复执行。

## 实现思路

错误对象携带阶段、错误码、可重试性和 trace ID；只对允许的瞬时错误做带抖动的有限退避，遵守服务端重试提示。

## 练习

建立错误矩阵，为每类错误指定用户提示与恢复动作。

## 验收

结构错误不进入工具；权限错误不重试；重复工具请求不产生重复副作用。
