# 可观测性：请求轨迹与质量反馈

> 本章为学习导读与实践要求，后续补充可运行实现。

## 场景与目标

用户说答案错误，但只保存了最终文本，无法判断是检索还是生成问题。

## 从前端经验出发

沿用埋点、日志、指标和 tracing，为一次任务关联检索、模型、工具和 UI 状态。

## 类比的边界

普通异常监控发现不了事实错误；完整保存提示与文档可能泄露敏感信息。

## 实现思路

记录 trace ID、阶段耗时、版本、文档 ID、工具状态与用量；默认脱敏并限制留存；另建离线评测与用户反馈渠道。

## 练习

用一条错误回答还原检索结果、提示版本和工具调用。

## 验收

能定位失败阶段；日志无密钥；权限与留存明确；线上反馈可以转成回归样例。
