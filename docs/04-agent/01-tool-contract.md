# 工具契约：把函数调用变成受控执行

> 本页保留旧 URL 与原导读练习，作为迁移入口。完整正文已迁至：[22 查询实时信息，为什么需要工具](../05-tools/22-live-tools.md)、[23 工具描述是给模型看的，执行校验是给系统做的](../05-tools/23-tool-contract.md)、[25 从只读到写操作：预览、确认与幂等](../05-tools/25-safe-writes.md)。以下是历史导读，不代表当前示例的覆盖范围；运行与验收以新正文为准。

## 场景与目标

模型想读取组件信息，也可能请求发布文档或修改仓库。

## 从前端经验出发

沿用 API 契约、参数校验与权限模型，把工具看成可受控调用的能力。

## 类比的边界

工具 schema 不是授权；用户可读文档不代表可修改资源；模型生成的参数不能直接执行。

## 实现思路

区分只读和写入工具；执行端验证身份、参数和资源范围；写入使用幂等键、授权与必要确认；结果返回结构化状态。

## 练习

模拟未知工具、越权参数、重复提交和工具超时。

## 验收

违规调用被执行端阻止；写入副作用至多按业务约定发生一次；超时后能查询状态并对账。
