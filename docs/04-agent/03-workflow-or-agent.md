# 工作流还是 Agent：把自由度放在需要的地方

> 本页保留旧 URL 与原导读练习，作为迁移入口。完整正文已迁至：[24 固定流程能完成的任务，先不要交给 Agent](../05-tools/24-workflow.md)、[26 固定流程的分支越来越多，下一步该由谁决定](../06-agent/26-agent-decision.md)、[29 和固定工作流做一次公平对比](../06-agent/29-comparison.md)。以下是历史导读，不代表当前示例的覆盖范围；运行与验收以新正文为准。

## 场景与目标

查询组件文档本来只有固定步骤，却被改成任意工具探索。

## 从前端经验出发

借鉴固定业务流程与插件扩展的取舍，先判断任务路径是否可预先定义。

## 类比的边界

Agent 不是更高级的工作流；自由选择行动通常增加延迟、成本和验证难度。

## 实现思路

固定路径用工作流；仅把不可预判的步骤交给模型决策；限制工具集合、行动范围与预算；与固定流程基线比较。

## 练习

分别用固定检索回答流程和受限 Agent 完成相同任务集。

## 验收

以成功率、延迟、费用和失败解释比较；只有验证过的收益才支持增加自主性。
