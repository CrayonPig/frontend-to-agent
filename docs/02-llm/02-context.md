# 上下文与 Prompt：管理输入依赖

> 本页保留旧 URL 与原导读练习，作为迁移入口。完整正文已迁至：[05 Prompt、上下文与输出契约](../01-first-call/05-prompt-contract.md)、[31 上下文不是越多越好](../07-capabilities/31-context.md)、[39 Prompt 改了，如何知道哪一版影响了结果](../08-operations/39-prompt-versions.md)。以下是历史导读，不代表当前示例的覆盖范围；运行与验收以新正文为准。

## 场景与目标

对话越来越长，费用上升，旧约束开始干扰新问题。

## 从前端经验出发

借鉴状态管理与依赖注入，区分任务目标、规则、历史、检索证据和工具结果。

## 类比的边界

Prompt 不是可靠的权限系统；长上下文不能保证模型使用了正确证据。

## 实现思路

固定规则与外部数据分层；按任务选择历史，必要时摘要并保留来源；设置输入预算；把关键业务约束交给代码执行。

## 练习

分别去掉无关历史、加入冲突文档和外部恶意指令，比较行为。

## 验收

任务依赖可解释；外部内容不能授权工具；摘要遗漏有检测方式；输入量可测量。
