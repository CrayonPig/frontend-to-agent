# LLM 调用契约与结构化输出

> 本页保留旧 URL 与原导读练习，作为迁移入口。完整正文已迁至：[03 一次模型调用里发生了什么](../01-first-call/03-model-call.md)、[04 把第一条请求接进我们的应用](../01-first-call/04-application-request.md)、[05 Prompt、上下文与输出契约](../01-first-call/05-prompt-contract.md)。以下是历史导读，不代表当前示例的覆盖范围；运行与验收以新正文为准。

## 场景与目标

页面需要展示组件名称、参数与来源，模型却返回一段不稳定的自由文本。

## 从前端经验出发

把模型适配层视为接口适配器，为输入、输出、流式事件和错误建立明确契约。

## 类比的边界

JSON 解析或 schema 校验只验证形状，不验证组件存在、参数真实或引用可靠。

## 实现思路

定义最小输出 schema；逐层做解析、结构与业务校验；流式片段按协议组装，完成后再验证整体；不完整结果不能驱动副作用。

## 练习

构造缺字段、截断、拒答、错误组件名与错误来源样例。

## 验收

有效结果才进入业务流程；无效结果有明确恢复路径；不同供应商差异被适配层隔离。
