# 检索：关键词、语义与混合召回

> 本页保留旧 URL 与原导读练习，作为迁移入口。完整正文已迁至：[15 先用关键词把组件找到](../03-knowledge/15-keyword-search.md)、[16 名字不同、意思相近，怎么找到相关资料](../03-knowledge/16-semantic-search.md)、[17 两路结果都有用，如何合并和重排](../03-knowledge/17-hybrid-rerank.md)。以下是历史导读，不代表当前示例的覆盖范围；运行与验收以新正文为准。

## 场景与目标

精确组件名搜不到，模糊描述又只返回名称相似的无关组件。

## 从前端经验出发

借鉴站内搜索，先建立关键词检索基线，再评估语义召回、融合与重排。

## 类比的边界

向量相似度不是置信度；混合检索也不会自动提升所有查询的质量。

## 实现思路

构建精确名称、别名、意图与版本查询集；比较关键词与语义候选；融合排序需统一策略；权限过滤须在可信端执行。

## 练习

记录候选数、相关文档命中、排序位置与检索延迟。

## 验收

用标注集报告 Recall@k 与排序质量；解释各类查询的增益和退化；越权文档不进入生成上下文。
